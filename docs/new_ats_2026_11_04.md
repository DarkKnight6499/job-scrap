## Behavior

- Lever `team` matches `categories.team` exactly, including case. Dates still use `createdAt` in UTC.
- JazzHR reads `/apply/<id>/<title>` links from the listing, deduplicates IDs, and reads each detail page. JSON-LD supplies metadata when present. Visible location text is a fallback. Only exposed `datePosted` values become dates; absent dates stay blank.
- Workable POSTs an empty search to `https://apply.workable.com/api/v3/accounts/<slug>/jobs`. Expected response fields: `results`, `total`, `nextPage`; each result uses `shortcode`, `title`, `location`, `remote`, `published`. The next request sends `nextPage` as `token`. Missing rows, repeated tokens, and the `max_pages` ceiling return incomplete results. Default ceiling: 40 pages.
- NAS reads `https://<host>/jobs-site.xml` as a sitemap `urlset`. Job detail URLs supply stable IDs, titles, locations, and descriptions. Sitemap `lastmod` supplies the date, marked `posted_source="approx"` because modification does not establish original publication.
- TalentBrew `filter` keeps cards containing the case-insensitive substring in their URL or visible anchor text. All listing pages are still read. No date is invented. `"filter": "lhh"` excludes cards without that substring, including some LHH roles whose title and URL omit the brand. This is a substring filter, not complete business-unit coverage.
